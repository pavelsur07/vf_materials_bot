# План MVP: генерация PNG-слайда

## Цель

Реализовать упрощённый MVP модуля генерации изображений для Telegram-канала,
сайта и других мессенджеров.

Пользователь отправляет сюжет через существующую админку и получает один
PNG-файл размером **1080×1350** в фиксированном «Стиле 1». Без каруселей,
редактора слайдов, публикации в Telegram, выбора шаблонов и генерации PPTX.

## Пользовательский сценарий

1. Пользователь открывает страницу **«Генерация слайда»** в админке.
2. Вводит сюжет, например: «Финансовый директор анализирует падение
   выручки компании».
3. Нажимает **«Сгенерировать»**.
4. Система ставит фоновую задачу и показывает статус.
5. После завершения отображается изображение.
6. Пользователь может скачать PNG или сгенерировать новый вариант.

Повторная генерация создаёт новую запись и не удаляет предыдущий результат.

## Конвейер генерации

```text
Сюжет
  → формирование визуального промпта по правилам «Стиля 1»
  → адаптер сервиса генерации изображений
  → получение исходного изображения
  → проверка и нормализация до 1080×1350 PNG
  → сохранение файла
  → отображение результата в админке
```

Генерация выполняется через существующую очередь `jobs`, чтобы HTTP-запрос
админки не зависел от времени ответа внешнего сервиса.

## Единый стиль

Стиль должен быть отдельной версионируемой конфигурацией, а не набором строк,
разбросанных по коду:

```text
style_id: style_01
version: 1
model: выбранная модель
prompt_template: постоянное описание стиля
negative_prompt: нежелательные элементы
aspect_ratio: 4:5
output: 1080×1350 PNG
```

Тестовая конфигурация стиля: [docs/style_01.json](style_01.json).

В шаблоне стиля фиксируются:

- цветовая палитра;
- освещение и атмосфера;
- тип композиции;
- уровень реализма или иллюстративности;
- детализация и фактура;
- свободное место под будущий текст, если оно понадобится;
- запрет текста, логотипов и водяных знаков.

Для повторяемости важно использовать одну модель и одинаковые настройки
генерации. Если сервис поддерживает референсное изображение или seed, их
следует сохранять, но не считать seed гарантией одинакового стиля.

Когда появится второй стиль, добавляется `style_02`, а не отдельная ветка
логики по всему проекту.

## Важное ограничение про текст

В MVP изображение генерируется **без надписей**. Генеративные модели часто
искажают текст, особенно кириллицу.

Если позднее понадобится заголовок, правильная схема:

```text
AI-фон → отдельный рендерер текста → итоговый PNG
```

Текст, логотип и контакты должны накладываться детерминированно, а не
рисоваться нейросетью.

## Предполагаемое размещение в архитектуре

```text
vashfindir/
├── modules/slides/
│   ├── dto.py          # параметры и результат генерации
│   └── use_cases.py    # запуск и обработка сценария
├── domain/slides.py    # стиль, ограничения и валидация результата
├── agents/concrete/
│   └── slide_prompt.py # при необходимости — формирование визуального промпта
├── integrations/
│   ├── image_generator.py       # интерфейс генератора
│   └── <provider>_image_generator.py
├── apps/admin/routes/slides.py  # тонкие HTTP-роуты
└── apps/worker/handlers.py      # обработчик задачи генерации
```

Админка не должна напрямую обращаться к API генерации изображений.

## Хранение

Одна запись в БД на каждую генерацию:

- сюжет;
- `style_id` и версия стиля;
- итоговый визуальный промпт;
- модель и внешний идентификатор запроса;
- статус `queued / generating / ready / failed`;
- путь к итоговому файлу;
- сообщение об ошибке;
- автор;
- даты создания и завершения.

Сами изображения хранятся файлами, а не в SQLite:

```text
data/generated/slides/<generation_id>/original.png
data/generated/slides/<generation_id>/slide.png
```

Исходный ответ провайдера полезно сохранять отдельно до обрезки и
нормализации.

## Практические ограничения MVP

- минимальная и максимальная длина сюжета;
- понятное сообщение при отказе внешнего сервиса;
- таймаут и ограничение повторных попыток;
- защита от повторной отправки формы;
- проверка, что итог действительно PNG размером 1080×1350;
- авторизация и CSRF через существующие механизмы админки;
- никаких API-ключей в коде — только конфиг и `.env`.

### Этап 6. Подключить реальный сервис генерации

Добавить конкретный адаптер и настройки:

- endpoint и модель;

- сохранение внешнего идентификатора;
- понятная ошибка для отказа генерации.

Не логировать ключ и не передавать провайдеру лишние данные.

Для MVP выбран OpenAI-совместимый Images API: запрос отправляется на
`<base>/images/generations`, negative prompt добавляется в текст промпта, а
поддерживаемый портретный размер `1024x1536` после ответа нормализуется до
1080×1350. Основная модель OpenAI — `gpt-image-2.5-flare` с `quality=high`;
модель `gpt-image-1.5` устарела. Для MiniRouter добавлена отдельная ветка
адаптера: модель `openai/gpt-image-2.5-flare` принимает только `1024x1024`,
`quality=low` и PNG, поэтому квадратный результат центральной обрезкой
приводится к 1080×1350.

**Результат:** появляется настоящее изображение в выбранном стиле.
**Проверка:** реальная генерация через админку, файл корректно скачивается

## Критерий готовности MVP

Из админки по одному сюжету создаётся скачиваемый PNG размером 1080×1350,
статусы и ошибки видны пользователю, а результат можно воспроизвести или
объяснить по сохранённым промпту, модели и версии стиля.

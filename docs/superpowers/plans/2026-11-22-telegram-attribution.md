# План внедрения атрибуции и лид-магнитов в Telegram

**Цель** — привязать `/start` к реестру ссылок и выдаче материалов, сохранить историю касаний, синхронизировать лиды с Bitrix24 и выгружать данные для отчётной таблицы.

**Архитектура** — бизнес-сценарии в `vashfindir/modules/attribution/`, операции с данными в `vashfindir/domain/attribution/`, модели в общей SQLite. Telegram-роутеры, страницы существующей админки и обработчики существующего воркера вызывают модуль через точки входа платформы. Источник требований — ТЗ «Атрибуция источников и лид-магниты в Telegram-боте» из задачи.

**Порядок исполнения** — после согласования реализовать этапы последовательно. Для каждого этапа сначала добавить целевые тесты, затем реализацию и проверку. После зелёных `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy vashfindir/` и `uv run pytest` сделать отдельный коммит и сообщить, что сделано и как проверить вручную.

## Состояние репозитория

- Платформа `0.1.0`, Python `>=3.12`, локально `3.14.4`. Зафиксированы aiogram `3.31.0`, aiohttp `3.14.3`, SQLAlchemy `2.0.54`, aiosqlite `0.22.1`, Alembic `1.20.0`, FastAPI `0.143.0`, Jinja2 `3.1.6`, bcrypt `5.0.0`, itsdangerous `2.2.0`, pytest `9.1.1` и pytest-asyncio `1.4.0`. Локальная SQLite `3.46.1`.
- `/start` обрабатывает `vashfindir/modules/onboarding/handlers.py`. Параметр команды сейчас игнорируется. `OnboardingUseCase` сохраняет пользователя, проверяет подписку и выдаёт один `LEADMAGNET_URL` либо предлагает проверить подписку. Повторную проверку обрабатывает отдельный callback. Сессия БД и use case приходят из middleware.
- `vashfindir/db/models.py` содержит `User`, `Job` и `SlideGeneration`. В `users` уже есть уникальный `tg_id`, внутренняя PK `id`, имя, username и `created_at`. Последняя миграция Alembic — `7cdabea4159b`. Подключения к SQLite включают WAL и таймаут блокировки.
- Мини-UI — веб-админка `/admin/`. FastAPI отдаёт Jinja2-страницы с Pico CSS 2, формы защищены CSRF, пароль проверяется через bcrypt, сессия хранится в подписанной HTTPS-cookie. В сессии есть логин администратора. Привязки к Telegram ID нет.
- `domain/jobs.py` предоставляет очередь `jobs`, `apps/worker/` опрашивает её каждые пять секунд. Сейчас зарегистрированы генерация слайдов и суточный подсчёт пользователей. На старте прерванные задачи переводятся в `failed`. Повтор Битрикс24 и расписание на конкретное местное время потребуют явной обработки.
- Настройки загружает `core/config.py` из `.env`, публичный шаблон — `.env.example`. Пуш в `master` запускает GitHub Actions. `deploy/deploy.sh` обновляет зависимости, один раз запускает Alembic и перезапускает systemd-сервисы. Воркер включается `WORKER_ENABLED=true`.
- Базовый прогон в текущем checkout — 173 теста прошли, Ruff и mypy прошли. Есть предупреждение Starlette об используемом `TestClient`. Тесты покрывают сценарий подписки, пользователей, очередь, админку и HTTP-адаптеры. Общая фикстура создаёт SQLite in-memory из моделей, поэтому проверку самих миграций добавим отдельно. Копии текущей базы в рабочем каталоге нет.

## Решения для согласования

1. **Подписка и обычный `/start`.** Предлагаю сохранить старый путь для `/start` без кода и добавить рядом кнопку каталога, привязанную к `direct`-касанию. Для кодов, которые ведут в новый каталог, выдавать материал после существующей проверки подписки. При неизвестном коде без подходящего префикса или неактивном магните показывать приветствие и меню. Если новые магниты должны выдаваться без подписки или домашним экраном обычного `/start` сразу должно стать меню, это меняет маршрут пользователя и должно быть подтверждено отдельно.
2. **Доступ к мини-UI.** Предлагаю раздел в существующей веб-админке. После входа по паролю администратор один раз за сессию подтверждает свой `tg_id` через приватный чат с ботом. Одноразовый код из браузера отправляется отдельной командой, чтобы не создавать ложное `/start`-касание. На каждом запросе раздела проверяется актуальный список разрешённых ID. Если нужен экран внутри Telegram Mini App, потребуется другой вход через проверенный Telegram `initData`.
3. **Повторы Bitrix24.** Предлагаю первую попытку сразу и пять повторов через `1, 5, 15, 60, 240` минут. Итого максимум шесть попыток. При лимите в пять попыток всего один интервал из ТЗ нужно исключить.
4. **Лид при открытии меню.** Предлагаю создавать лид после регистрации касания, даже если человек не выбрал материал. Для такого лида использовать заголовок `Telegram: {имя}`, а после успешной выдачи добавить префикс к уже полученным магнитам в CRM. Заголовок при этом остаётся исходным.

# Атрибуция и лид-магниты

## Запуск

Примените миграции на тестовой SQLite через `uv run alembic upgrade head`. Перед обновлением продакшена проверьте миграцию на копии текущей базы. На сервере миграции применяет `deploy/deploy.sh`.

| Переменная | Назначение |
|---|---|
| `ATTRIBUTION_ENABLED=true` | Включает атрибуцию, каталог и раздел админки. |
| `ATTRIBUTION_BOOTSTRAP_ADMIN_TG_IDS=[123456789]` | Начальный список Telegram ID. После сохранения настроек действует список из админки. |
| `ATTRIBUTION_SECRET_KEY` | Общий для админки и воркера ключ Fernet. Нужен для шифрования вебхука, введённого в UI. |
| `ATTRIBUTION_MAGNET_DIR` | Каталог серверных файлов лид-магнитов. По умолчанию `./data/lead_magnets`. |
| `ATTRIBUTION_BOT_USERNAME` | Необязательное имя бота для ссылок. Если пусто, админка использует Telegram `getMe`. |
| `WORKER_ENABLED=true` | Включает существующий воркер обработки Bitrix24 и уведомлений. |

Установите зависимости через `uv sync`. Сгенерируйте секрет через
`uv run python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'`
и сохраните результат в серверной `.env`. Для обновления серверной `.env` используйте
`deploy/update-env.sh`. Админка и воркер используют один ключ. Сохраните ключ
при ротации других секретов, иначе потребуется заново ввести URL вебхука.

Локально запускайте процессы в отдельных терминалах.

```bash
uv run python -m vashfindir.apps.bot
uv run python -m vashfindir.apps.admin
uv run python -m vashfindir.apps.worker
```

Войдите в `/admin/`, откройте «Атрибуция» и отправьте показанную команду
`/admin_auth …` в личный чат с ботом. Вернитесь в браузер и завершите вход.
Доступ к разделу сверяется с актуальным списком разрешённых Telegram ID.

Создайте лид-магнит и ссылку. Для типа «Файл» укажите `file_id` этого бота
или путь внутри каталога, например `file:checklist.pdf`. Обычный `/start`
сохраняет сценарий подписки и прежний материал. Каталог новых материалов
появляется при наличии активных магнитов. Новые магниты тоже требуют подписки.

## Bitrix24

1. В CRM откройте настройки пользовательских полей сущности «Лид». Создайте
   пять полей и выпишите их коды `UF_CRM_…`. Telegram ID храните в строковом
   поле, чтобы сохранить длинные идентификаторы. Для username, кода первого
   касания, кода последнего касания и списка префиксов используйте строковые
   поля. Для кодов касаний задайте длину не менее 72 символов.
2. Создайте входящий вебхук с правами CRM от пользователя, которому доступно
   создание, чтение и изменение лидов и добавление комментариев.
3. На вкладке «Атрибуция → Bitrix24» укажите HTTPS URL вебхука, `SOURCE_ID`
   и пять кодов. URL вводится как пароль и сохраняется зашифрованным в SQLite.
   Пустое поле URL при редактировании сохраняет ранее введённый вебхук.
4. Включите воркер. Пока вебхук отсутствует, касания остаются в `pending`
   без запросов к CRM и без расхода попыток. После сохранения воркер
   автоматически подхватит накопленные касания. Отправка выполняется
   последовательно для каждого Telegram ID.

Для временной ошибки используется первая попытка и до пяти повторов через
1, 5, 15, 60 и 240 минут. После исчерпания повторов можно запустить обработку
из журнала «Касания». Для повторных касаний CRM получает код последнего
касания и список выданных магнитов. UTM первого касания сохраняются.

[Входящие вебхуки](https://apidocs.bitrix24.com/local-integrations/local-webhooks.html) ·
[Поля лидов](https://apidocs.bitrix24.com/api-reference/crm/leads/userfield/) ·
[Лимиты запросов](https://apidocs.bitrix24.com/settings/performance/limits.html)

## Выгрузки

В разделе «Выгрузки» скачиваются `links.csv` и `touches.csv`. Без дат выгружается вся
история. При задании дат обе границы периода включены. Дата относится к
созданию записи в часовом поясе из настроек. Тестовые касания включаются
отдельным флажком.

Формат — UTF-8 с BOM, запятая, первая строка с заголовками. Даты имеют формат
`YYYY-MM-DD HH:MM:SS`, календарные даты размещения выгружаются с временем
`00:00:00`. Логические значения — `1` и `0`. Десятичный разделитель — точка.

```text
code,magnet_prefix,magnet_name,utm_source,utm_medium,utm_campaign,utm_content,utm_term,placement,period_start,period_end,budget,status,created_at
touch_id,created_at,tg_id,username,code,raw_payload,code_status,magnet_prefix,magnet_source,utm_source,utm_medium,utm_campaign,utm_content,utm_term,is_new_user,magnet_delivered,bitrix_lead_id
```

В `touches.csv` колонка `code` содержит код ссылки либо `direct` / `unknown`.
Для неизвестного кода исходный параметр остаётся в `raw_payload`.

## Служебный чат

В «Атрибуция → Настройки» укажите ID служебного чата, часовой пояс, время
сводки и порог для доли direct и unknown. Бот должен иметь право писать в чат.

Сводка приходит за завершённые календарные сутки. Доля для предупреждения
считается за семь завершённых суток. Для каждой активной ссылки с началом
размещения проверяются первые семь календарных дней этого размещения.
Тестовые касания исключаются из сводки. Если воркер запущен после времени
отправки, он подбирает сегодняшнюю сводку при ближайшей проверке расписания.

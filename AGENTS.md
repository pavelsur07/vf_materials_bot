# AGENTS.md — «Ваш Финдир»

Чат-бот «Ваш Финдир» — Telegram-бот на Python, ведущий пользователя по сценариям
(меню, кнопки, диалоги) по финансовой тематике.

Этот файл — обязательные правила для человека и ИИ-агента. Он короче ума:
когда правило мешает, сначала обнови этот файл, потом код — а не наоборот.

## Стек (зафиксирован, не менять без обновления этого файла)

- Python 3.12+, asyncio
- aiogram 3.x (Router, F-фильтры, FSM для диалогов)
- SQLite через SQLAlchemy 2.x (async) + Alembic для миграций
- uv — управление зависимостями и окружением (никакого pip/poetry)
- ruff — линтер и форматтер, mypy — строгая типизация
- pytest + pytest-asyncio — тесты

## Структура проекта

```
vf_materials_bot/
├── pyproject.toml          # зависимости, конфиг ruff/mypy/pytest
├── .env.example            # шаблон переменных (BOT_TOKEN=...); .env — в .gitignore
├── bot/
│   ├── __main__.py         # точка входа: polling или webhook — по MODE из .env
│   ├── config.py           # pydantic-settings, чтение .env, единственный источник конфига
│   ├── handlers/           # роутеры: по одному файлу на сценарий/раздел меню
│   ├── dialogs/            # FSM-состояния и тексты многошаговых сценариев
│   ├── keyboards/          # inline/reply клавиатуры, по одному модулю на раздел
│   ├── services/           # бизнес-логика без aiogram-импортов (чистые функции/классы)
│   ├── db/
│   │   ├── models.py       # SQLAlchemy-модели
│   │   ├── session.py      # engine, session factory
│   │   └── migrations/     # Alembic
│   └── middlewares/        # логирование, throttling, db-сессия в data
└── tests/                  # зеркалит структуру bot/
```

Новый модуль кладётся строго по слою. Если непонятно куда — значит, это
`services/`, а импорты aiogram в нём — признак ошибки проектирования.

## Архитектурные правила (не превращаемся в кашу)

1. **Слои только вниз**: handlers → services → db. Обратных и поперечных
   импортов нет. `services` и `db` не импортируют aiogram — их можно тестировать
   без Telegram.
2. **Хэндлер — тонкий**: принять update, вызвать сервис, ответить. Никакой
   логики, SQL и f-строк с бизнес-правилами в хэндлерах.
3. **Один сценарий = один роутер = один файл** в `handlers/`. Файл больше
   ~300 строк — сигнал разбить сценарий.
4. **Тексты сообщений — отдельно от логики**: в `dialogs/` (или `texts.py`
   раздела). В коде хэндлеров нет длинных литералов.
5. **Клавиатуры — только в `keyboards/`**, собираются функциями-фабриками,
   callback_data — через `CallbackData`-фабрики aiogram, а не сырые строки.
6. **FSM-состояния — через `StatesGroup`**, по одной группе на диалог, рядом
   со сценарием. Никаких магических строк состояний.
7. **Конфиг — только через `bot/config.py`**. Запрещены `os.environ` вне него
   и захардкоженные токены/ID. Секреты — в `.env` (в git не коммитим, шаблон —
   `.env.example`).
8. **БД — только через миграции Alembic**. Руками схему не правим; изменил
   модель — сгенерируй миграцию. Сессия пробрасывается через middleware,
   не создаётся в хэндлерах.
9. **Логирование — `logging` (или loguru, если добавлен в зависимости),
   никаких `print`**. Логируем события, не токены и не персональные данные.

## Стиль кода

- Типы обязательны: все публичные функции аннотированы, mypy проходит без ошибок.
- async везде, где I/O. Блокирующие вызовы (файлы, requests, тяжёлый CPU) —
  только через `asyncio.to_thread` / пул.
- Имена: хэндлеры `on_<событие>`, клавиатуры `<раздел>_kb()`, сервисы — глагол
  (`get_user`, `save_answer`). Русский язык — только в текстах для пользователя,
  в коде и комментариях — английский/русский по существу, но консистентно внутри модуля.
- Комментарии — только про «почему», не про «что». Закомментированный код не коммитим.
- Не добавляем зависимость, пока задачу нельзя решить стеком выше. Новая
  зависимость = запись в этом файле, если она меняет стек.

## Команды (используй их, не выдумывай свои)

```bash
uv sync                      # установить зависимости
uv run python -m bot         # запустить бота (polling/webhook — по MODE в .env)
uv run ruff check --fix .    # линт
uv run ruff format .         # форматирование
uv run mypy bot/             # типы
uv run pytest                # тесты
uv run alembic revision --autogenerate -m "..."   # миграция
uv run alembic upgrade head                       # применить миграции
```

Перед коммитом обязательны зелёные: `ruff check`, `ruff format --check`,
`mypy`, `pytest`. Не работает — чиним, а не обходим флагами.

## Тестирование

- Пишем тесты на `services/` и на разбор callback_data — это ядро, которое
  ломается первым. Тесты на хэндлеры — через моки `Message`/`CallbackQuery`,
  без реального Telegram.
- Фикстуры БД — SQLite in-memory, через `pytest-asyncio`.
- Тест живёт в `tests/` и зеркалит путь модуля: `bot/services/x.py` →
  `tests/services/test_x.py`.

## Git

- Ветки: `feature/<краткое-имя>`, коммиты на русском или английском в
  повелительном наклонении, один коммит — одно осмысленное изменение.
- В `.gitignore`: `.env`, `*.db`, `__pycache__/`, `.venv/`, `.idea/`.
- Не коммитим: токены, реальные БД с пользователями, логи.

## Как развивать проект (рецепты)

**Добавить новый сценарий/раздел меню:**
1. Тексты и `StatesGroup` → `dialogs/<имя>.py`.
2. Клавиатуры → `keyboards/<имя>.py`.
3. Роутер → `handlers/<имя>.py`, зарегистрировать в `bot/__main__.py`.
4. Логика посложнее ветвления → `services/<имя>.py` + тест.
5. Нужны данные → модель + миграция Alembic.

**Добавить поле в БД:** изменить модель → `alembic revision --autogenerate` →
проверить сгенерированную миграцию глазами → `alembic upgrade head`.

**Новый секрет/настройка:** поле в `config.py` + строка в `.env.example`
(без значения). Никогда — реальное значение в репозиторий.

## Антипаттерны (запрещено)

- Хэндлеры-простыни со всей логикой внутри.
- Один `handlers.py` на весь бот.
- SQL в хэндлерах; создание engine/session в хэндлерах.
- `callback_data="btn_1"` строками без фабрик; parse callback через `split`.
- Глобальные переменные для состояния пользователя (только FSM/БД).
- `except Exception: pass`, отключённые проверки ruff/mypy без причины в коде.
- Бот, который падает от одного плохого update: каждый роутер отвечает за
  свои ошибки, общий error handler обязателен.
